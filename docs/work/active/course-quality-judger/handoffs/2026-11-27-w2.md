  `/my-yoma` only when every condition below holds (`shouldRedirectToMyYoma`):
  - the switch is on and the session is authenticated;
  - the session has no Admin or OrganisationAdmin role;
  - Yoma's profile is complete (`isUserProfileCompleted`), so `Global.tsx`'s update-profile dialog is done;
  - the settings dialog is configured or skipped;
  - `GET /pathway/me/profile` returns 404.

  The redirect happens at most once per browser session (sessionStorage `myYoma.firstVisitRedirected`, also set when
  `/my-yoma` loads). "Go to Yoma home" links to `/?home=1`, which opts out for the session, so it cannot loop.
  (`ProfileCompletionWizard.tsx` is not mounted anywhere at `cfa9dc0`. The dialogs that do open live in
  `Global.tsx`.)

  - "Building your path" follows: a path draws itself for at least 1.5 s, has a Skip button, and lasts until the

## Requests to the lead

1. **Contract or API (A3): prefilled answers for hidden questions.** `PathwayProfileRequest` needs every field, but
   the web does not know the preference values behind `answeredFromPreferences`. For hidden questions left empty,
   the web sends neutral values (`withPreferenceFallbacks`):
   - `knownSkillKeys: []`;
   - the country question's "anywhere" option, which means `countryId: null`;
   - the **middle hours option** (5).

   The goal and starting point are never filled; if either has no answer, it is asked. **A3 should prefer the stored
   Yoma preference over the request value for keys in `answeredFromPreferences`, and must not write these fallbacks
   back into preferences.** A cleaner fix is a contract change: the questions endpoint returns the prefilled answers,
   e.g. `preferenceAnswers: Partial<PathwayProfileRequest>`. The web would then seed `initialAnswers` from it and
   drop the fallbacks.
2. **Merge conflict expected in `pages/my-yoma-preview.tsx`.** W1 adds a `view=map` case there. My version
   restructured the view list (`VIEWS`) and the 404 rule, so keep both cases.
3. `pages/index.tsx` is changed only by the hook import and one call.
4. With the web switch on and the API's `Pathway:Enabled` off, `/pathway/me/profile` returns 404. The web reads
   that as "no path", sends the youth to `/my-yoma` once, and the questions call then fails with an error and a
   retry. Keep both switches on together, as the demo does.
