## Gotchas

- **CPU speed.** 58 to 98 seconds per check on an idle 4-core CPU. While the machine was busy, one check took 4 min
  50 s, against an API limit of 300 seconds; past the limit, the rule-based result stands. Keep the presenting machine
  idle, or use `qwen2.5:1.5b` or the native Ollama app.
- **The small model is cautious.** On the 8 named courses, 7 ended as expected. It lowered course 101 from Verified to
  Needs review: the "AI can only lower" rule working, but the walkthrough's 101 step differs when the AI is on.
- **Prompt change.** E1 added two sentences to the shared system prompt: score each criterion exactly once, and
  confidence is a decimal from 0 to 1. Without them the 3B model's answers were rejected as Invalid. This also changes
  what Anthropic would receive. `docs/ziqi-handover/prompts/` is regenerated.
- **New settings, all off or safe by default:**
  - `AI:OpenAICompatible:IsLocal` defaults to false, so a remote endpoint is never recorded as free by accident.
  - `CourseQuality:PrePublish:UseAI` defaults to false: the partner draft check does not call the model, because those
    calls are not metered and are too slow on a CPU.
  - `CourseQuality:LinkHealth:BudgetInSeconds` is 240: links not started in time come back as Timeout.
- **Ingress.** The deployed ingress closes requests after 300 s (`helm/`, left unchanged). Keep the AI timeout plus the
  page fetch below that in production.
- **Sandbox-only shims** used for this verification, none of them committed:
  - the API and website ran natively;
  - the fixture pages ran on a separate, routable Docker network (`11.66.1.0/24`), because the demo's fixtures network
    is internal by design;
  - the test accounts were created by running `src/keycloak/scripts/users.sh` natively.
