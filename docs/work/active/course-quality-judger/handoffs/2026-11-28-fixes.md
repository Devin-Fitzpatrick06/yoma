## What Was Done

1. **`AI:OpenAICompatible:IsLocal` defaults to false** (`CourseQualityAIOptions.cs`, `appsettings.json`). A remote endpoint
   left at the default now records a null cost, or a priced one, instead of "$0 Local · free". `start.sh` already sets it
   explicitly: `true` for `--local-ai` and `--local-ai-url`, and `false` for `--ai-url`. `docker-compose.demo.yml` passes it by
   name. Docs updated: the SETUP.md AI table, the demo README and iteration-5.md.
   Tests: `RemoteOpenAICompatible_LeftAtTheDefault_IsNotRecordedAsFree`, the appsettings test (now `False`), and
   `OpenAICompatible_IsTheProvider_…` (endpoint not local by default, local when set). The tests' `AIOptions` helper sets
   `IsLocal = true` explicitly for its localhost URL.
2. **`CourseQuality:PrePublish:UseAI`** (default false). With it off, `CourseQualityDraftService` swaps the injected
   provider for a `CourseQualitySourcePageReader` (unless the provider already is one), so the draft check never calls the
   model. The page cache key carries `ai` or `reader`. Documented in the SETUP.md switches table, the LIVE-RULES-MOCKED
   draft-check row and LIMITATIONS.
   Tests: `UseAI_IsOffByDefault`, `UseAIOff_ReadsThePageWithTheKeylessReader_AndNeverCallsTheModel` (an enabled mock model
   gets no calls, and the result equals a reader-only draft), `UseAIOn_CallsTheConfiguredProvider`, and
   `AppSettings_LeaveTheDraftCheckWithoutAI`. The draft test harness now sets `UseAI = true`, so the existing tests keep
   calling the provider they pass.
3. **Link health budget, `CourseQuality:LinkHealth:BudgetInSeconds`** (default 240). `LinkHealthService` takes
   `IOptions<CourseQualityOptions>` (it reads only `LinkHealth`; `Enabled` is still ignored) and an optional `TimeProvider`.
   It checks the deadline before each link starts. A link not started in time is returned as `Timeout` with "Not checked:
   the check ran out of time. Run these links again.", with no HTTP status or duration, so the counts still sum to `checked`.
   A link already started finishes within `LinkCheck:TimeoutInSeconds` (15 s). LIMITATIONS now notes that "Run AI check"
   must stay under the ingress's 300 s `proxy-read-timeout` (helm not changed), and SETUP describes the budget.
   Tests: `OutOfTime_LinksNotStarted_AreTimeout_NotChecked_AndTheCountsAddUp` (a fake clock moved 100 s per request:
   3 requested, 2 not checked, 1 invalid, counts sum to 6), `WithinTheBudget_EveryLinkIsChecked`,
   `Budget_DefaultsTo240Seconds`. E2's `Service_DependsOnlyOnTheSafeChecker_NotOnTheCourseQualitySwitch` (no `IOptions`)
   became `Service_UsesTheSafeChecker_AndWorksWithTheCourseQualitySwitchOff`, which is behavioural.
4. **CLI proxy names** (`scripts/link-health/check-links.mjs`). `validateHop` takes an origin: `input`, `redirect` or
   `sitemap`. With `--proxy`, a failed local lookup is left to the proxy only for `input`. A redirect hop is Refused with
   "…could not be looked up on this machine, so the redirect target could not be verified locally and the redirect was not
   followed." A sitemap link (from a URL, a file or an index's child sitemap) is Refused with "…came from a sitemap and could
   not be looked up on this machine…". `readInput` now returns `{ urls, fromSitemap }`. The README safety section is
   updated.
   Tests: the new `test/proxy-names.test.mjs` uses a fake CONNECT proxy that records its targets. It covers 6 cases: input
   left to the proxy, a redirect to an internal name refused and never CONNECTed, a same-host redirect refused, sitemap URL
   links, sitemap file links, and an index child sitemap.
5. **Unpriced and remote runs.** `CourseQualityAIUsageSummary.UnpricedRuns` (null cost) and `RemoteRuns` (`!IsLocal`) are
   counted over every stored usage, not just the recent 20. Web: the same fields are in `courseQuality.ts`.
   `formatTotalCost` returns "$X known · N runs without a price" whenever `unpricedRuns > 0`, and "$0.00 (local, free)"
   only when `isLocal` and `remoteRuns === 0` and the cost is 0. The panel note uses `summary.unpricedRuns`. A new
   `AI_USAGE_MIXED_HISTORY_FIXTURE` panel is in `/ziqi-admin-preview`.
   Tests: C# `Summary_CountsUnpricedAndRemoteRuns_AcrossAllHistory_NotJustTheRecentList`, asserts added to the summary,
   empty and serialisation-shape tests, and 2 new web tests in `AIUsage.helpers.test.ts`.
6. **start.sh**: with `--local-ai-url` (and also `--ai-url`, the same bug), a URL on `localhost` or `127.0.0.1` is rewritten
   to `host.docker.internal` for the API, with a printed note. The host reachability check maps it back to localhost as
   before. `bash -n` is clean. The option parsing was run offline in a scratch copy: localhost, 127.0.0.1 with https,
   host.docker.internal unchanged, `localhostfoo.example` unchanged, `--local-ai` unchanged.
7. **Base URL with a query**: `OpenAICompatibleChatClient.Endpoint(Uri)` builds `GetLeftPart(Path)` + `/chat/completions`
   + the original query, and drops a fragment. For example, `…/v1?api-version=X` becomes `…/v1/chat/completions?api-version=X`.
   Test: `Request_KeepsABaseUrlQuery_AfterThePath_AndDropsAFragment` (4 cases). SETUP.md documents it.

## Gotchas

- Behind `--proxy` on a machine with no DNS at all, every redirect, even http→https on the same host, is now Refused. That
  is the rule as specified. Run without `--proxy`, or where local DNS works, for redirect-heavy lists.
- A deployment that relied on the old `IsLocal = true` default for a local model must now set it explicitly.
  The demo does.
- The draft check's AI usage is still not stored when `UseAI` is on (nothing about a draft is stored). That is documented.
