## Built

**W1 pre-publish check (API)**
- `POST /api/v3/courseQuality/organization/{organizationId}/draft/check` (`CourseQualityController.CheckDraft`), roles
  `Admin, OrganisationAdmin`. Authorization follows `ListFixNotes`: `IOrganizationService.IsAdmin(organizationId, true)`.
  The route's organisation is the one checked; a body `organizationId` is ignored.
- 404 (`EntityNotFoundException`) unless `CourseQuality:PrePublish:Enabled`, before the authorization check and before any
  fetch. Only `PrePublish:Enabled` gates it, not `CourseQuality:Enabled`.
- Body: `CourseQualityDraftRequest`. It takes the fields of `OpportunityRequestBase` that the checks read, and every one is
  optional, so a half-typed form is checked rather than rejected. Other form fields are ignored. It is a separate DTO
  because MVC treats the base class's non-nullable `Title`/`Description`/`Categories`/... as required.
- `CourseQualityDraftService` builds the listing in memory as it would read once published: status Active, the
  organisation's real status, and the type, commitment interval and engagement type resolved through the lookups. Custom
  fields are stored the way the custom field service stores them. It then runs **the same engine call** as after
  publishing: Learning goes through `CourseQualityEngine.Assess` with format detection and the registered page reader,
  Event and ImpactAction get the listing checks only, and Job goes through `AssessJob`. A type that is not checked after
  publishing (not in `VerifyTypes`, or Job with `Jobs:Enabled` off) gets a 400 `ValidationException`. Nothing is
  stored: the service has no repository.
- The response is `DraftCheckResult`, mirroring `courseQuality.ts` field for field in camelCase. `DraftCheckField`
  values are camelCase strings (constants), not an enum, because the API writes enums in PascalCase.
  - `fixes` are the same issues a fix note lists, with the checks' own partner wording. `hardGate` is the criterion's
    `HardGateFailed`.
  - The field map: LinkWorks goes to url, and FormatIdentified to title. DatesAccurate goes to dateStart, or to dateEnd
    when the start is plausible and an end exists. DataComplete goes to the missing field: dateStart, commitment, or
    countries for a job. ListingLive goes to dateEnd when the listing has ended, dateStart for a past webinar, and other
    otherwise. JobOpen goes to url, dateEnd, or other when the listing is hidden or the organisation is inactive.
    JobDetailsClear and NoScamSignals go to description, and JobFresh to dateStart.
  - `summary` is one sentence, for example "Two fixes and this course will be verified." or "The link could not be
    opened just now, so a reviewer will look at this course after you publish."
- Link check: the existing safe checker runs with its own `PrePublish.LinkTimeoutMilliseconds` timeout (linked token).
  - A timeout becomes `Inconclusive(Timeout)`, which is never a hard gate. `linkChecked` is false for Inconclusive and for
    Missing.
  - A definite failure (404, NXDOMAIN, invalid) is still a hard fail, as after publishing.
  - A request the caller cancels still throws.
- Repeated calls stay cheap through an in-process cache (`CourseQualityDraftCache`, bounded at 2000 entries):
  - a link result per URL for 5 minutes, or 30 seconds after a timeout;
  - a page reading per hash of everything it reads, for 5 minutes, so an edit is read again but not fetched again;
  - suggestions the same way.
- Suggestions ("draft this for me") come through a new optional seam, `ICourseQualityDraftSuggester`. The service takes
  `IEnumerable<ICourseQualityDraftSuggester>`, so with none registered `suggestions` is `null`. With an enabled one:
  - the result is a list holding only summary, dateStart, dateEnd and skills, one per field, capped at 1000 characters;
  - the list is empty when the link opened no page.
  - No implementation exists yet (see Requests).

**W4 Impact Action listing checks**
- `ImpactAction` was added to `CourseQualityOptions.SupportedVerifyTypes`. With `CourseQuality:VerifyTypes` including
  it, impact actions get the listing checks (live, link, real dates, enough data). They get no format and no grade, and
  a fix note uses "listing" wording.
- `CourseQualityRules.Noun(ImpactAction)` = "impact action". Events and jobs are unchanged.

**Lead's addition: drop-off slot on the reviewer assessment**
- Added `CourseQualityAssessment.DropOff` (`CourseQualityDropOff { status: Collecting|Available, rate: number|null,
  note }`, mirroring `StepDropOff`). The service sets it in `SetGrades`, so the reviewer search, Assess and Review all
  return `{ status: "Collecting", rate: null, note: "Collecting from the pilot" }`. It is not stored. It is named
  `CourseQualityDropOff` so it cannot collide with a Pathway `StepDropOff` class that A3 or A4 may add; unify if wanted.
