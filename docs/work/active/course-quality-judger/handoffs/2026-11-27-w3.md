## Built

**W1: the Ziqi check panel** (`components/CourseQuality/DraftCheckPanel.tsx`, `.helpers.ts`, `.fixtures.ts`)

- On the create and edit listing form (`pages/organisations/[id]/opportunities/[opportunityId]/index.tsx`),
  only when `NEXT_PUBLIC_PREPUBLISH_ENABLED`. Off: the page renders exactly as before (same classes, no panel).
- Reads the draft live without re-rendering the 4 800-line editor: the callback form of `watch()` on the
  step 1, 2 and 4 forms, taking only each step's own fields (every step form is seeded with the whole
  listing, so the others hold stale copies): `pickDraftFields`.
- `checkDraftListing` 800 ms after the last change, the request before it aborted (`createDebouncedCheck`);
  no request for an empty form or an unchanged draft. 404 hides the panel for the rest of the visit; other
  errors keep the last result with a quiet note and retry on the next change.
- Shows the predicted verdict (Verified / Needs a look / Not verified yet), a score ring, `summary`, each
  fix (hard gates first) with reason, recommendation and "Go to <field>" (names the step when it is another
  one), the "link not confirmed yet" note, and "Draft this for me": suggestions with Apply (title, summary,
  description, link only; dates and lists are shown without Apply), or "Available when AI is configured".
- "Go to field": `DRAFT_FIELD_TARGETS` maps each `DraftCheckField` to the wizard step and selectors
  (General 1: title, summary, description, link; Details 2: languages, location, commitment, dates;
  Skills 4). It switches step through the existing `onStep` (so the unsaved-changes dialog still applies),
  then scrolls and focuses after the step's scroll-to-top. `difficulty` and `other` have no field: no button.
- Layout: a sticky 320 px column from `xl`; below `xl` a fixed bottom drawer with a status line, collapsed
  by default (`aria-expanded`, `aria-controls`). Verdict in an `aria-live="polite"` region. Reduced motion
  respected. With the switch on, the page container is `overflow-clip` instead of `overflow-hidden` (a
  scroll container stops `sticky`) and gets bottom padding for the drawer.
- Never blocks saving: nothing in the panel touches validation or the submit buttons.

**W2: badges on public surfaces**

- `api/services/partnerBadges.ts`: `getPartnerBadges(ids, signal)` → `GET /pathway/badges/organizations?ids=a&ids=b`
  (repeated keys, ASP.NET default binding; ids unique, lowercased, sorted, at most 100); 404 → `[]`.
  Pure parts in `partnerBadges.helpers.ts`.
- `components/Opportunity/PartnerBadgeChip.tsx`: `PartnerBadgesProvider` (one react-query request keyed on the
  sorted ids, `["pathway","partnerBadges",ids]`), `PartnerBadgesScope` (fetches only when no provider above),
  `PartnerBadgeChip`. Renders nothing while loading, without a provider, or for None / NotEnoughGraded.
  Gated on `NEXT_PUBLIC_PATHWAY_ENABLED` (the endpoint 404s with the API switch off anyway).
- The chip sits in `OpportunityOrgCountriesRow`, so it appears on DefaultCard, JobCard, LearnerCardTile and both
  opportunity page headers. `OpportunitiesGrid` wraps its items in one scope; `OpportunityPublicDetails` wraps
  its header (one request for the one organisation).
- `PartnerBadgeCard`: Platinum has its own purple-tint card and ringed icon; "Ziqi partner badge"; a
  "Reviewed each quarter · next review 1 Jan 2027" line from `reviewDue`; heading id from `useId`.
- Organisation page: `pages/organisations/[id]/index.tsx` does not exist, so the badge card is on
  `info.tsx` (the organisation overview, signed in), below the overview.

**Labels**: "Ziqi check", "Ziqi partner badge"; at the lead's request also `components/NavBar/Navbar.tsx`
"Course Quality" → "Ziqi" (both menu items, routes unchanged).

**Preview**: `/ziqi-draft-preview?result=notVerified|needsLook|verified|empty|checking|error&drawer=open`, gated
like `my-yoma-preview` (404 in production unless `NEXT_PUBLIC_COURSE_QUALITY_DEMO`). A stand-in form so Go to and
Apply work, the chips at every level, and a Platinum and a Gold card. Example data, labelled.
