## What Was Done

- **Endpoint** `POST /api/v3/courseQuality/links/check`, Admin only, body `LinkHealthRequest` → `LinkHealthReport`, one
  new action `CheckLinks` in `CourseQualityController` (service injected with `[FromServices]`, so the constructor is
  untouched and E1's changes there merge cleanly). Registered with one line in `Startup.cs`:
  `AddScoped<ILinkHealthService, LinkHealthService>()`.
- **Contract** `CourseQuality/Models/LinkHealthContract.cs` mirrors the "Iteration 5" TS block exactly: `Urls`,
  `Platform`; enum `LinkHealthStatus` (Ok, Redirected, NotFound, Broken, Blocked, Timeout, Invalid, Refused) serialised as
  names by the API's string enum converter; `LinkHealthResult` (url, status, httpStatus, finalUrl, durationMs, reason);
  `LinkHealthReport` (platform, checked, counts with **every** status, zero included, results, dateChecked).
- **`LinkHealthService`** reuses `ICourseQualityLinkChecker`, the existing safe fetcher. No second HTTP client. It:
  - trims, drops blanks and dedupes (by normalised absolute URI, first-seen order). It returns 400 (`ValidationException`)
    for an empty list or more than 200 distinct URLs, before any request;
  - marks non-http(s) or unparsable input `Invalid` itself, without a request (on Linux `/path` parses as `file://`,
    so an explicit scheme is required);
  - groups by host and runs up to `MaxConcurrentHosts = 8` hosts in parallel (`Parallel.ForEachAsync`), one host's
    links in turn, so the checker's `LinkCheck:MinHostIntervalInMilliseconds` spaces them without holding up other
    hosts;
  - names each outcome with `Classify` (pure, public static). The checker failure mapping is: NotFound → NotFound;
    DomainNotFound, ServerError, UnexpectedStatus, TooManyRedirects, ConnectionError (TLS included), EmptyResponse →
    Broken; AccessBlocked (401/403/bot header) and RateLimited → Blocked; Timeout → Timeout; BlockedAddress → Refused,
    with a specific reason for a port, credentials or a redirect; InvalidUrl → Invalid, or Broken when it came from a
    redirect `Location`;
  - reads a page that loaded with `LinkHealthPageRules`: a bot wall → Blocked; a page that says it is gone → NotFound
    (reusing `CourseQualityPageMatch.IsSoftNotFound`, plus an "expired" pattern); a sign-in wall → Blocked (reusing
    `IsLoginWalled`, but its wording check runs only on short pages, so "log in to comment" on a long page stays Ok);
    then Redirected when the final host (ignoring `www.`) or path (ignoring case and a trailing slash) differs.
    http→https and query changes are not a move.
  - It has no dependency on `CourseQualityOptions` and ignores `CourseQuality:Enabled`, because it is a tool. A test
    asserts this.
- **CLI** `scripts/link-health/check-links.mjs` (Node 18+, no npm packages): reads .txt / .csv (auto column
  `url`/`link`/`URL`/`… link`, or `--column`; `;`-separated CSV detected) / sitemap (file, `.xml.gz` or URL; an index is
  followed one level, at most 50 children). Options are `--platform --concurrency --per-host-delay-ms --timeout-ms
  --max-redirects --out --md --json --user-agent --allow-private --proxy --quiet`. It sends a browser User-Agent,
  follows at most 5 redirects and validates each hop. It uses the same statuses, reasons and pacing scheme as the API.
  It refuses after `dns.lookup` using the API's address ranges, and pins the socket to the checked addresses. The
  exit code is always 0.
- **Shared rules** `scripts/link-health/link-health-rules.json` holds the gone, bot-wall and sign-in regexes, generated
  from the C# sources. `LinkHealthServiceTests.CliRulesFile_MatchesTheApiPatterns` extracts the `[GeneratedRegex]`
  literals from `CourseQualityPageMatch.cs` and `LinkHealthPageRules.cs` and fails if the JSON drifts.
- **README** `scripts/link-health/README.md` covers the commands for GenU, YouthHub and 1MiO, the status meanings, the
  page rules, the safety notes, and a curl example for the API with a `<ADMIN_ACCESS_TOKEN>` placeholder.
- **Sample** `scripts/link-health/examples/sample-urls.txt` mixes 5 Yoma course URLs (alison, atingi, open.edu, netacad,
  coursera from the live catalogue cache), a `.invalid` domain, a missing alison page, two malformed lines, a private IP,
  the metadata IP and a duplicate. No generated reports are committed.
- **Tests**: `LinkHealthServiceTests` (62 cases) runs the real checker over a fake resolver and a fake handler. It covers
  every status, empty / >200 / exactly 200 plus duplicates / duplicate normalisation, refused private targets (literal,
  resolved, redirect, port, credentials), counts, platform, parallelism bounds, per-host pacing, caller cancellation, the
  Admin-only route attribute and the rules-file drift guard. `scripts/link-health/test/check-links.test.mjs` (node:test,
  8 tests) runs the CLI against a local server: every status, txt/csv/sitemap input, CSV/MD reports, the CSV formula
  guard, the refusals and the address policy.

## Gotchas

- The API uses the checker's bot User-Agent (`YomaCourseQualityBot/1.0`); the CLI uses a desktop browser's. A few sites
  may answer them differently, so the API reports more Blocked.
- The checker refuses ports other than 80/443, so an intranet link on `:8080` is Refused by the API. The CLI allows it
  only with `--allow-private`. Link-local and cloud metadata addresses stay refused in the CLI even with
  `--allow-private`.
- With `--proxy`, a name this machine cannot resolve is left to the proxy, which cannot be pinned. Only literal
  addresses and local names are refused up front then (documented in the README).
- The page text the checker returns has `nav` and `footer` stripped (`CourseQualityPageText`), and the CLI does the
  same, so wording in a footer never decides a status.
- A request of 200 links on a single host takes about 200 × 1.1 s ≈ 3.7 minutes, because pacing is per host. The
  request is bound to `RequestAborted`, so a client that gives up cancels the run.
- `Classify` closes over a local `Result` function, and the `EveryCheckerFailure_HasAStatus` test fails if a new
  `CourseQualityLinkFailure` value is added without a mapping.
