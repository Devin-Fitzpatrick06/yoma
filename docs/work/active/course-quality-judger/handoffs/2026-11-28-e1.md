## What Was Done

- **Config `AI` section** (`CourseQuality/Models/CourseQualityAIOptions.cs`): `Provider` (None | Anthropic | OpenAICompatible,
  default Anthropic), `OpenAICompatible { BaseUrl, Model, ApiKey, IsLocal = true, TimeoutInSeconds = 300, MaxTokens = 1024, MaxPageChars = 6000 }`,
  `Prices` (model → `{ InputPerMillionUsd, OutputPerMillionUsd }`, empty by default). Cost is 0 when IsLocal, prices × tokens / 1e6
  (rounded to 6 dp) for a priced remote model, null for an unpriced one. A configuration key cannot contain `:`, so
  `qwen2.5:3b` is priced under `qwen2.5_3b` (the lookup tries the exact name first, then the name with `:` changed to `_`).
- **One prompt, one parser** (`CourseQuality/Helpers/CourseQualityAIPrompt.cs`): SystemPrompt, OutputSchema, SchemaName
  `course_check`, `BuildUserMessage` (a nonce per call for the delimiters, with an optional page cut) and `Parse` with the
  "AI can only lower" ceiling. These moved out of `AnthropicCourseQualityProvider`. That class keeps `private const string SystemPrompt/OutputSchema`
  as aliases of the shared constants, so `HandoverExportTests` reads them by reflection as before.
- **Shared flow** (`CourseQuality/Services/CourseQualityModelProvider.cs`, abstract): no page text means no call; the keyless reader's result is the ceiling;
  the call is sent and metered; the reply is parsed. Every call returns `CourseQualityAICall(Result, Usage)` through the new
  `ICourseQualityMeteredAIProvider`. `CourseQualityProviderFallback` moved to the Domain (`CourseQuality/Services/`). When the model gives no answer,
  the fallback runs the reader and **keeps the usage of the failed call** on the reader's result, so a Declined, Failed or Invalid call is still stored and counted.
- **Anthropic**: now a thin subclass. `AnthropicCompletion` carries `usage.input_tokens` / `output_tokens` from the SDK response.
  Behaviour is unchanged: it is selected only when `AI:Provider` is Anthropic and a key is set.
- **New project `Yoma.Core.Infrastructure.OpenAICompatible`**, added to the sln and referenced from the API. It has no NuGet packages:
  `OpenAICompatibleChatClient` POSTs `{BaseUrl}/chat/completions` with `response_format: {type: json_schema, json_schema: {name, strict: true, schema}}`,
  `temperature: 0`, `max_tokens` and `stream: false`. It sends a bearer key only when one is configured, follows no redirects, caps the response at 1 MB and does not use the link checker.
  Outcomes: `finish_reason` other than `stop`, or a `refusal`, is Declined; a reply that is not in the schema is Invalid; HTTP errors, a malformed envelope, a connection error or a timeout are Failed.
  All three fall back to the reader. Page text, and the structured data, are cut to `MaxPageChars`.
- **Selection**: each infrastructure Startup registers itself only for its own `AI:Provider` value. Each also registers a `CourseQualityAIEndpoint` describing the configured model,
  and the Domain registers `CourseQualityAIEndpoint.None` as the default. With `None`, only the keyless reader runs.
- **Usage on every AI call**: `CourseQualityAIUsage` (provider, model, endpointHost = `host:port` or null for Anthropic, isLocal, inputTokens, outputTokens, costUsd, durationMs,
  dateRun, outcome) → `CourseQualityAIResult.Usage` → `CourseQualityAssessment.AIUsage`. It is stored on the record and returned as `aiUsage` by assess, reviewer search and review.
  It is null when no AI ran.
- **Migration `ApplicationDb_CourseQuality_AIUsage`** (`20261128011006`): one nullable `jsonb` column, `CourseQuality.Assessment.AIUsage`. The repository writes null, never an empty string,
  because an empty string gives the 22P02 error noted on Criteria. The JSON is stored the same way as the other columns (Newtonsoft, PascalCase, enums as strings).
  The migration was generated with dotnet-ef 10 and re-indented to the repo's 2-space style. The snapshot diff is +3 lines.
- **`GET /api/v3/courseQuality/ai/usage` (Admin)** → `CourseQualityAIUsageSummary` (`CourseQualityAIUsageService`). The totals cover every stored row with usage, history included,
  because each reassessment is a run. The totals query reads only the AIUsage column; the recent list reads 20 rows.
  **Contract addition requested by the lead:** `CourseQualityAIRun.organizationId` (Guid), next to `opportunityId`. The TS contract needs it at merge.
- **Prompt wording** (changes the handover file `docs/ziqi-handover/prompts/course-check.system-prompt.txt`, regenerated with `ZIQI_HANDOVER_UPDATE=1`).
  Two clarifications were needed before the local model could answer at all: "Score each of these four criteria exactly once" and
  "Confidence is a decimal from 0 to 1, such as 0.45, never a percentage". Without them `qwen2.5:3b` answered with `confidence: 70`, and then with a duplicated
  FormatIdentified. The parser correctly rejected both as Invalid. Its strictness was **not** relaxed. These sentences now go to Claude too.

## Gotchas

- A small model can still answer outside the schema. That is Invalid and falls back to the reader, which is the intended safety behaviour. The live test asserts Answered,
  so it can be flaky on weaker models.
- `CourseQualityAIEndpoint` describes the configured model, not the model of past runs. Each run's usage carries its own provider and model.
- Ollama ignores `strict` numeric bounds. The output schema has no `minimum`/`maximum`, because Anthropic structured output does not accept them. The range checks are in the parser.
