## Merged, and how overlaps were settled

- **Jobs use the other account's pipeline** (`CourseQuality:Jobs:Enabled`, on in the demo): job checks read the listing
  and its partner feed (JobOpen, NoScamSignals, JobDetailsClear, JobFresh) and jobs get A–D grades ranked only against
  other jobs. Its finding decided this: job pages cannot be read reliably (JobJack shows one app shell for every job,
  every Jobberman page contains "Job is no longer available").
- **Events keep the iteration-3 listing checks** (`CourseQuality:VerifyTypes`). Job was removed from `VerifyTypes`; the
  service queues jobs through `Jobs:Enabled` instead (`DueTypes`).
- **Demo jobs import is the other account's** (`seed/generate-jobs-sql.mjs`): it records each feed job's partner so the
  API skips the link check, and skips duplicates as the live unique indexes would. `fetch-live-catalogue.mjs --jobs`
  fetches every live job by default; `--max N` stops early. The duplicate import step in `start.sh` was removed, so the
  other account's step imports, checks and grades jobs, then saves the database again.
- **Grade factors**: the course `Outcomes` factor and the six job factors share the enum. Tests that counted every enum
  value as a course factor now count `CourseQualityGradingDefaults.Factors`.
- **Fix notes**: jobs keep "This job is not verified yet"; events say "listing".
