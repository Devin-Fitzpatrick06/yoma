## What Was Done

### W0: `Pathway:Enabled` and the `[PathwayEnabled]` attribute

- `PathwayOptions.Enabled` (bool, default false); `appsettings.json` `Pathway:Enabled: false`.
- **Attribute: `[PathwayEnabled]`**, class `Yoma.Core.Api.Attributes.PathwayEnabledAttribute`
  (`src/api/src/application/Yoma.Core.Api/Attributes/PathwayEnabledAttribute.cs`). One line on a controller or action:

  ```csharp
  using Yoma.Core.Api.Attributes;
  ...
  [ApiController]
  [PathwayEnabled]
  ```

  It is a resource filter with `Order = int.MinValue`, so it runs before model binding and every other filter and answers a bare 404
  while the switch is off. It reads `IOptionsMonitor<PathwayOptions>` per request (a config reload applies without a restart); with
  no options registered it counts as off.
- Applied to `PathwayController` and `PathwayBadgeController`. **A4: put `[PathwayEnabled]` on `PathwayStepController`.** A test
  (`Switch_IsOnEveryPathwayController`) fails for any controller under `api/v3/pathway` without it, so it catches a missing one after merge.
- Also in that file: `app.UsePathwayEnabledSwitch()`, middleware that does the same check from endpoint metadata **before
  authentication**. It is not wired in (Startup is not mine); see Requests.

### W2: Platinum, `reviewDue`, hints

- `PartnerBadgeLevel.Platinum` between Gold and NotEnoughGraded (strings on the wire; matches `pathway.ts`).
- Default `Pathway:PartnerBadges:Levels:Platinum`: `MinShareTopGrades 0.75`, `MaxShareHeldBack 0.02`, `MinimumGradedCourses 25`
  (placeholders). `PartnerBadgeThreshold` has a new optional `MinimumGradedCourses`: a level can need more graded courses than the
  badge minimum (10). Null on Bronze to Gold, so they behave as before. Binding still merges by level; removing Platinum from the
  dictionary makes Gold the top again.
- `nextLevelHint` covers Gold to Platinum. When the count is short, the hint names it first: "For Platinum: 5 more graded courses (20
  now, 25 needed), and about 1 more course at grade A or B (70% now, 75% needed), and 1 fewer course held back as Not verified (5%
  now, at most 2%). …". At Platinum there is no next level; only the waiting count remains.
- **Fairness guard kept:** waiting courses count in neither share, shares are null below the minimum, and the hint still names the
  waiting count.
- `PartnerBadge.ReviewDue` (`DateOnly`, JSON `"reviewDue": "2027-01-01"`, the same format as the web fixtures) is the first day of
  the next calendar quarter in UTC. On a quarter's first day, the review is the start of the following quarter.
  `PartnerBadgeCalculator.Calculate` now takes `now`, and `PartnerBadgeCalculator.ReviewDue(now)` is public.

### W2: batched endpoint

- **Final contract** (agreed with the lead): `GET /api/v3/pathway/badges/organizations`, anonymous, `[PathwayEnabled]` →
  `PartnerBadge[]`.
  - Ids come as repeated keys (`?ids=a&ids=b`, which the web client sends), as one comma-separated value (`?ids=a,b`), or both mixed
    (`?ids=a,b&ids=c`). The controller binds `[FromQuery] string[]? ids`, and each value is split on commas.
  - Returned in the order asked. A repeated id appears once.
  - Organisations that do not exist or are not Active are left out silently. The single endpoint gives them all the same 404, so
    this reveals no more.
  - 400 (DataAnnotations `ValidationException`) for no ids, a malformed or empty GUID, or more than 50 distinct ids. Repeats do
    not count towards the limit. The limit is `Pathway:PartnerBadges:MaxOrganizationsPerRequest` (50).
- **Three queries, however many ids:**
  1. The active organisations among the ids.
  2. The grades of their visible Learning courses (a JOIN on a course subquery, with `OrganizationId` carried through).
  3. The latest assessments of the same courses.

  Counting per organisation is in memory (`CountByOrganization`).
- `GET organization/{id}` now goes through the same path with one id. It reads the organisation repository instead of
  `IOrganizationService.GetByIdOrNull`, so its result is identical to the batched one (a test proves it). `IOrganizationService` is
  no longer a dependency of `PathwayBadgeService`.
