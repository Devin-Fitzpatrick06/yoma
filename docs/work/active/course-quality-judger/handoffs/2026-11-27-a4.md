## What Was Done

- **Storage** (the one migration, `ApplicationDb_Pathway_Steps`, timestamp `20261127203614`). Three tables in the `Pathway` schema:
  - `StepLock`: one row per user and opportunity, unique. Unpinning deletes the row.
  - `StepSwap`: user, replaced, replacement, date. It is a history in the order made.
  - `StepEvent`: user, opportunity, `GoalKey`, `StageOrder`, `Event` (varchar: Shown, Started, Completed, Swapped,
    Dismissed) and date. It has four indexes: (User, Opportunity, Event, Date) for the Shown repeat check,
    (Opportunity, Event), (GoalKey, StageOrder, Event) and (Event, Date) for the aggregates.
  - Foreign keys point to User and Opportunity with NoAction. Entities and repositories are in
    `Infrastructure.Database/Pathway/`; the domain records are in `Pathway/Models/PathwayStepRecords.cs`.
  - The migration was made with `dotnet-ef` 10.0.13. The repo has no tool manifest, so I installed it to a scratch path.
  - The generated files were re-indented to the repo's 2-space style. The snapshot diff is additions only.
- **Stored `IPathwayStepStore`** (`PathwayStepStore`) is registered with `AddScoped` after the no-op `TryAddScoped`.
  It returns locks in creation order and swaps in the order made.
- **`PathwayStepService` / `IPathwayStepService`** with **`PathwayStepController`**, route `api/v3/pathway`:
  - `PUT me/steps/{id}/lock` {locked} returns MyYoma. The step must be on the youth's path (404 otherwise). Locking
    twice does nothing. The response is the path rebuilt by `IPathwayService.Get()`.
  - `GET me/steps/{id}/alternatives` returns at most 3 PathwayCourse.
  - `POST me/steps/{id}/swap` {replacementOpportunityId} returns MyYoma.
    - The replacement must be one of the (at most 3) alternatives. An empty id or the step itself is a 400.
    - It stores the swap and removes any pin on the replaced step.
    - **It records a `Swapped` event for the replaced step on the server, as the lead asked.** The web map sends no
      Swapped event.
  - `POST me/events` PathwayStepEventRequest returns 204.
    - An empty, unknown or nonexistent opportunity is a 400, and so is an undefined event type.
    - A `Shown` event for the same user and step within 30 minutes is dropped. Other event types are always recorded.
    - Each event is stamped with the goal key and the stage order taken from the current path. The stage is null when
      the step is not on the path.
  - `GET health` (Admin) returns PathwayHealth.
    - `stepsTracked` counts distinct (goal, stage, opportunity); `events` is the row count.
    - `dropOff` is `Collecting`, rate `null`, note "Collecting from the pilot" while `Pathway:DropOffAvailable` is not
      true. That key is read through `IConfiguration`, not `PathwayOptions`, which belongs to A1 and A3.
    - With the switch on, `ComputeDropOff` counts distinct youth who started a step. Below `Pathway:MinimumGroupSize`
      (20) it stays Collecting. From 20 it gives the share of started (youth, step) pairs not completed.
  - `GET yoid/me` returns MyPathSummary built from `Get()`, or 404 when the youth has not onboarded. Next step = the first
    step not Completed, in stage order.
- **How completion is detected (task item 3):** there is no clean existing hook on verification, so nothing writes
  `Completed` events automatically. The aggregate counts a step as completed when it has a `Completed` event or a
  MyOpportunity Verification with status Completed. This is read only when the switch is on and the group has at least 20.
- **`DropOff` grade factor:**
  - I appended it last to `CourseGradeFactor`, so the stored values of the job factors do not move.
  - Its default is weight 0, neutral 50, parameter MinGroupSize 20.
  - In `CourseQualityGradingEngine`, a one-line `DropOff()` always returns no data with the reason
    "Drop-off: collecting from the pilot." That file belongs to A2.
  - It is not in the job rubric. A saved rubric that predates it gets it at weight 0 through `WithNewFactors`.
- **Tests:**
  - `Pathway/PathwayStepServiceTests.cs` (23 tests): storage through the store, lock, swap and alternatives validation,
    events and the Shown window, the health empty state, the switch, the minimum group, the summary.
  - `Pathway/PathwayStepWiringTests.cs` (5 tests, one a 6-case theory): registration, each endpoint's verb, template and role, the 204, the alternatives
    adapter.
  - `CourseQuality/CourseQualityDropOffFactorTests.cs` (4 tests): the factor stays neutral and is never in the job rubric.

## Gotchas

- `RecordEvent` calls `IPathwayService.Get()` to find the stage, which builds the whole path once per non-repeat event.
  Repeated Shown events are dropped before that call. If it is too slow, cache the stage per user or have the web
  send the stage.
- Events need an onboarded youth: `Get()` returns 404 otherwise.
