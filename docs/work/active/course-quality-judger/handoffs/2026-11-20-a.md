# Handoff: jobs, part 1 (job checks)

Date: 2026-11-20. Branch: `feature/course-quality-judger`, on top of `5667e2fb`. Nothing here is committed yet; the
project lead approves commits.

## Why

Feedback from the last demo: expand beyond learning courses. Live Yoma has 10,101 jobs against 2,408 courses (also 41
tasks, 18 events, 10 other), so jobs come first.

## Found before building

- A 600-job sample (spread across the live catalogue) is all partner feeds: JobJack 400, Jobberman Nigeria 193, Jobberman
  Ghana 7. Pulled jobs are locked, have no closing date, and cannot be completed on Yoma (verification is off).
- Both feed syncs already mark a job deleted once it drops out of the full feed snapshot, and Jobberman already flags
  duplicate titles. So "is it still open" comes from the feed, not from crawling.
- Job pages cannot be read reliably: JobJack's link page is the same app shell for every job (the job sits behind a
  sign-in), and every Jobberman page contains "Job is no longer available" as a report-form option. Jobberman pages do
  carry JobPosting structured data (posted, closing date, salary), unused so far.
- Salary, schedule and industry arrive as job custom fields from the feeds, but the public search API returns no custom
  fields, so the sample could only use the description text.

## Built

- **Job checks** (`CourseQualityJobRules`), read from the listing and its feed only:
  - JobOpen (hard gate): active, organisation active, not hidden, closing date not passed; for a job posted on Yoma
    rather than pulled, the link to apply must work.
  - NoScamSignals (hard gate): fee or deposit to apply, requests for bank, ID or login details, apply-by-WhatsApp or
    Telegram, guaranteed jobs. A match right after a negation ("we never charge an application fee") does not count.
    A personal email address alone only lowers the score.
  - JobDetailsClear: pay amount, schedule or contract type, location, requirements, how to apply; custom fields or text.
    "Market related" pay does not count as an amount.
  - JobFresh: 100 up to 45 days, falling towards 50, 0 from 90 days. Soft, never a gate. Only for jobs posted on Yoma:
    a feed lists a job only while it is open, so a feed job's age is not checked and its score counts the other three
    (decided by the project lead, 2026-11-20).
- **Routing** (`CourseQualityEngine.AssessJob`): a definitely closed job is Not verified; a strong scam signal or an
  unconfirmed link goes to a reviewer with the quoted words; otherwise the score against the usual threshold of 80.
  Confidence is a fixed 0.9 (no page reader), less the inconclusive-link penalty.
- **Storage without a migration:** jobs use the existing assessment table with a new `CourseFormat.Job`, which also
  tells jobs from courses in queries. Job rubric version `jobs-v1` is separate, so job changes do not reassess courses.
- **Service:** `CourseQuality:Jobs:Enabled` (off by default) adds published jobs to the due queue. Feed jobs skip the
  link check. The review search takes `OpportunityType` (Learning or Job). Browse is unchanged: jobs get no status or
  ranking there yet. A job's format cannot be changed in review.
- **Web:** types and labels for the new criteria and the Job format, so the reviewer queue shows job cards and Verify
  never opens the format dialog for a job. No new screens.

## Verified

- API build 0 warnings; CourseQuality tests 959 total, 0 failed, 9 skipped (opt-in); `dotnet format --verify-no-changes`
  clean on the changed folders.
- Web: `tsc` clean, `pnpm lint` clean, `pnpm test` 428 of 428.
- Calibration over the 600 live jobs (opt-in test `Calibration_SummarisesASavedJobSample`, `COURSE_QUALITY_JOB_SAMPLE`):
  0 scam signals; Jobberman 199 of 200 Verified; JobJack 400 of 400 Verified. 389 of 400 JobJack jobs still have no pay
  amount ("Market Related"), which lowers their score (mean 92) but does not hold them back. Before age was dropped for
  feed jobs, 145 JobJack jobs were Not verified: 149 were 90 or more days old while the feed still listed them.

## Not verified

- Nothing has run against a database or in the demo; the service wiring is covered by build and type checks only.
- The checks have only seen description text. With the feeds' custom fields (production database), pay and schedule
  results will differ.
- No scam signal was seen in real data, so the patterns are tested on written examples only.
